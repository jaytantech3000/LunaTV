# 帐号同步页极简改造设计

## 目标

将 `/account-sync` 收敛为一个极简桌面同步页：

- 删除标题下说明文字
- 将“同步状态摘要”和“开启帐号同步”压缩为同一行双卡布局
- 删除“诊断详情”
- 增加“管理同步范围”
- 为管理员帐号增加单独的 `管理员设置` 同步项

## 非目标

- 不在本次设计中改动 `/config` 页结构
- 不在页面主区域保留大段 onboarding 表单
- 不把 `管理员设置` 继续拆成多个子域
- 不同步本地运行时状态、本地连接配置或诊断数据

## 版面结构

页面主体改为两层：

1. 顶部一行双卡
   - 左卡：`同步状态摘要`
   - 右卡：`开启帐号同步` / `立即同步`
2. 下方一张整行卡
   - `管理同步范围`

桌面端使用 `1/2 + 1/2` 布局，移动端自动上下堆叠。

## 交互设计

### 1. 标题区

- 保留 `桌面同步` 和 `帐号同步`
- 删除 `帐号同步` 下整行说明文字

### 2. 同步状态摘要

摘要卡只保留最少信息：

- 大状态：
  - `已连接并已登录`
  - `未启用`
  - `需要处理`
- 两条短信息：
  - `帐号：admin`
  - `状态：远端可达 / 登录失效 / 本地服务异常`

删除当前卡内的：

- 长段状态说明
- 同步范围展示
- 诊断入口

### 3. 开启帐号同步 / 立即同步

右卡不再承载完整流程说明，只承载动作。

#### 未开启

- 标题：`开启帐号同步`
- 短状态：`当前仍在使用本地模式`
- 主按钮：`开启同步`

点击后打开现有 onboarding 弹窗，复用当前 Web 登录、预览、执行流程。

#### 已开启

- 标题：`已开启帐号同步`
- 短状态：`当前使用 Web 帐号`
- 主按钮：`同步`

点击后立即执行一次手动同步。

#### 处理中

- 按钮进入 loading
- 卡内只显示一条短状态：
  - `同步中...`
  - `同步成功`
  - `同步失败：远端不可达`

### 4. 删除诊断详情

完全删除当前“诊断详情”区域，不保留折叠、不保留替代诊断卡。

错误反馈只保留在顶部双卡中：

- 摘要卡负责显示同步结果
- 操作卡负责显示操作结果

若本地服务状态读取失败，仅显示：

- `需要处理`
- 一条短错误说明
- `去配置` 链接

## 管理同步范围

新增单独卡片：`管理同步范围`

### 默认选项

默认展示当前 5 个用户数据域：

- 播放记录
- 收藏
- 追更
- 搜索历史
- 跳过片头片尾

### 管理员扩展项

当当前远端角色是 `owner` 或 `admin` 时，额外显示：

- 管理员设置

该项是单独顶层同步域：`adminsettings`。

### 选择方式

- 使用多选项控件
- 首次进入时，默认值取当前 `syncDomains`
- 如果远端未返回 `syncDomains`，回退到当前默认 5 项
- 普通用户永远看不到 `管理员设置`
- 若角色从管理员降级为普通用户，前端自动移除 `管理员设置`

### 保存策略

不单独提供“保存范围”按钮。

范围修改在用户点击 `同步` 时一起提交：

- 保存新的同步范围
- 立即执行一次手动同步

未开启状态下允许先调整范围；真正生效发生在“开启同步”完成后。

## 管理员设置的同步边界

`管理员设置` 同步的是管理员页可编辑的业务配置快照，不是整份 `AdminConfig`，也不是远端原始 `ConfigFile`。

包含：

- `SiteConfig`
- `AdFilterConfig`
- `SourceConfig`
- `CustomCategories`
- `LiveConfig`
- `PlayerEnhancementConfig`

不包含：

- `ConfigFile`
- `ConfigSubscribtion`
- `UserConfig`
- `userPasswords`
- `profile_sync.*`
- 本地服务运行时状态
- 诊断数据
- 重置动作
- 仅桌面本地生效的连接或运行参数

桌面端在 `web-first` 应用远端管理员设置时，不直接落远端原始 `ConfigFile`。本地服务根据结构化业务配置重建一份“去身份化”的 `ConfigFile`，同时保留本地 `auth.*` 与 `profile_sync.*`。

核心不变式：

- 默认管理员用户名固定为 `admin`
- `owner` 只表示角色，不再表示帐号名
- 任何 profile sync 或本地备份导入都不得改写设备本地身份层

设计原则是使用受控同步域，避免把本地环境配置或身份层误同步到远端。

## 后端设计

### 1. 新增同步域

扩展当前同步域定义：

- 现有：`playrecords` `favorites` `follows` `searchhistory` `skipconfigs`
- 新增：`adminsettings`

### 2. 新增手动同步接口

新增接口：

- `POST /api/profile-sync/sync-now`

请求体职责：

- 提交当前选择的 `syncDomains`
- 触发一次立即同步

接口行为：

1. 校验桌面已开启帐号同步
2. 校验同步域是否合法
3. 若包含 `adminsettings`，要求当前远端角色为 `owner/admin`
4. 读取本地用户数据快照
5. 若包含 `adminsettings`，只构造允许字段组成的业务配置快照
6. 按所选域同步到远端
7. 若 `web-first` 且包含 `adminsettings`，拉取远端业务配置快照并在本地重建去身份化 `ConfigFile`
8. 返回新的同步状态与最近一次执行结果

### 3. onboarding 对接

开启同步成功后需要立刻持久化当前范围选择，避免首次开启后还需要再点一次“同步”。

onboarding 若包含 `adminsettings`，也必须复用同一份受控业务快照构造逻辑，不能再上传整份本地 `adminConfig`。

### 4. 管理员配置读取脱敏

- `GET /api/admin/config` 对 `owner` 可保留完整配置
- 对 `admin` 只返回 `adminsettings` 所需的业务字段，不返回 `ConfigFile` 等 owner-only 敏感字段
- `web-first` 与 onboarding 的管理员设置读取逻辑必须只依赖这份脱敏后的业务快照

## 状态矩阵

### 未开启

- 左卡：`未启用`
- 右卡：`开启同步`
- 范围卡：可编辑默认范围

### 已开启且正常

- 左卡：`已连接并已登录`
- 右卡：`同步`
- 范围卡：可编辑当前范围

### 已开启但异常

- 左卡：`需要处理`
- 右卡：允许再次 `同步`
- 卡内显示一条短错误

### 本地服务读取失败

- 左卡：`需要处理`
- 右卡：禁用同步按钮
- 显示 `去配置`

## 测试要求

### 前端

- 标题下说明文字已删除
- 顶部为双卡布局
- 诊断详情已删除
- 管理员与普通用户看到的同步范围选项不同
- 已开启状态点击 `同步` 会立即发起请求
- 未开启状态点击 `开启同步` 会打开现有 onboarding 流程

### 后端

- `adminsettings` 仅允许 `owner/admin`
- 普通用户提交 `adminsettings` 会被拒绝
- 手动同步只处理所选域
- 不会把 `ConfigFile`、`UserConfig`、`userPasswords` 同步到远端
- `web-first` 会在本地重建去身份化 `ConfigFile`，并保留本地 `auth.*` 与 `profile_sync.*`
- `/api/admin/config` 对 `admin` 返回脱敏后的业务配置快照

## 风险与约束

- 当前仓库还没有“更新 syncDomains”的现成前端接口，本次需要新增接口与状态返回结构。
- 现有 onboarding 里只在首次主帐号迁移时附带管理员配置快照；改成长期可选同步后，后端必须把它提升为显式同步域，并改为受控字段白名单。
- 当前桌面端会用原始 `config.json` 回灌 `SourceConfig`、`CustomCategories`、`LiveConfig` 与播放器增强配置；如果不本地重建去身份化 `ConfigFile`，同步结果会被旧身份配置再次污染。
- `UserConfig.Tags` 与 `Users`/采集源权限联动；把它们继续放进 `adminsettings` 会间接改写用户权限并重引入帐号冲突。
- 删除诊断区后，错误文案必须足够短且足够准，否则用户会失去排障入口。

## 推荐实施顺序

1. 定义 `adminsettings` 同步域与后端校验
2. 增加管理员业务快照过滤与本地去身份化 `ConfigFile` 重建
3. 增加 `sync-now` 接口
4. 为 `admin` 角色的 `/api/admin/config` 增加脱敏返回
5. 新增同步范围卡
6. 改造顶部双卡布局
7. 删除诊断区并补齐前后端测试
