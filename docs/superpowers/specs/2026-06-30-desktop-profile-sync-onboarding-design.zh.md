# 桌面帐号同步开通设计

**目标**

把桌面端“手改 `profile_sync.api_base_url`”改成 `desktop-admin` 内可见、可执行、可预览的同步开通向导，并在开通时完成本地帐号资料迁移与当前剩余离线下载归属重绑。

**范围**

- 仅在 `desktop-admin` 暴露开通入口。
- 默认生产地址为 `https://luna.hkcu.qzz.io`。
- 本地全部帐号资料迁移到 Web：
  - 播放记录
  - 收藏
  - 追更
  - 搜索历史
  - 跳过片头片尾配置
- 当前仍然存在的一套离线下载不删除，只重绑到当前登录 Web 帐号。
- 仅允许 Web `owner/admin` 执行整套开通流程。

**非目标**

- 不改成桌面前端直连 Web。
- 不把开通入口放进用户菜单设置弹窗。
- 不尝试恢复已经被历史清理掉的离线下载归属。

**现状问题**

- 现在必须手动配置 `profile_sync.api_base_url`，没有正式入口。
- 直接开同步会把桌面切到远端帐号模式，但不会自动迁移本地帐号资料。
- 当前下载归属切换逻辑会在 owner 变化时清空离线下载，风险过高。
- 本地服务的远端登录 session 只在内存里，重启后丢失。

**设计**

1. `desktop-admin` 新增同步卡片和开通向导。
2. 向导先做远端登录、权限校验、迁移预览，再执行真正迁移。
3. 执行时由本地服务编排：
   - 登录 Web
   - 拉远端管理员配置
   - 计算帐号映射
   - 自动创建缺失的同名 Web 帐号，初始密码 `123456`
   - 调 Web 合并接口迁移每个本地帐号资料
   - 重绑当前剩余离线下载 owner
   - 把 `profile_sync.api_base_url` 写回桌面配置文件
4. 配置写入后不依赖手工改 JSON；前端刷新 desktop runtime，使桌面立即切到 sync 模式。

**帐号映射**

- 当前登录本地帐号 -> 当前登录 Web 帐号
- 其他本地帐号 -> 同名 Web 帐号
- 同名 Web 帐号不存在 -> 自动创建普通用户

**冲突策略**

- A: Web 优先
- B: 本地优先

**离线下载策略**

- 只处理当前仍存在的一套离线下载快照。
- 不上传文件到 Web。
- 只修改本地下载快照和资源索引里的 owner。
- 前端在帐号切换瞬间禁止走旧的“owner 变化即清空”路径。

**接口**

- Web 新增管理员资料合并接口：
  - 接收目标用户名、本地资料快照、冲突策略
  - 合并后写回目标用户资料
- 本地服务新增开通接口：
  - 预览
  - 执行

**错误处理**

- 远端登录失败：停在登录步骤，不写配置。
- 权限不足：明确提示只有 Web `owner/admin` 可执行。
- 创建用户失败：中止执行，不进入 sync 模式。
- 资料迁移失败：中止执行，不写配置。
- 离线下载重绑失败：中止执行，不写配置。

**测试**

- Web 合并纯函数测试：map 域和搜索历史的冲突策略。
- 本地服务纯函数测试：帐号映射、配置写回、离线下载重绑。
- 桌面下载归属测试：切换到 sync 后不触发 purge。
- `desktop-admin` 向导测试：预览、执行、成功提示、默认地址展示。
