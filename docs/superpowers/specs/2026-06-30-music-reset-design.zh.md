# LunaTV 音乐中心重置与占位期设计

**目标**

在当前 `desktop` 方向工作树中，先将现有 `/music` 对应的旧音乐 UI 和旧运行时行为安全下线，再为后续基于 `Rust + TypeScript + Tauri` 的 YesPlayMusic 重建预留干净入口。此次设计的重点不是立即重写新播放器，而是先完成“旧系统软下线、桌面基础设施保留、重建边界稳定化”。

**已确认决策**

1. 现有 `/music` 不继续增量改造，按“清空旧功能后重建”处理
2. 本阶段采用“仅清空 UI，保留桌面音乐基础设施”的路径
3. `/music` 路由保留，但改成“音乐中心重构中”的占位页
4. 现有旧音乐播放行为临时禁用，不允许后台恢复、继续播放或抢占音频输出
5. `/music` 相关旁路能力一并隐藏或禁用，包括主导航入口、tray 音乐控制、旧下载入口和旧音乐设置入口

**范围**

- 保留正式 `/music` 路由路径，但替换为占位页
- 移除旧音乐全局运行时挂载，确保应用启动后不会恢复旧音乐播放
- 隐藏侧边栏、移动底部导航以及其他可见音乐入口
- 停用旧音乐 tray 菜单与其对应前端联动
- 保留 `src-tauri/**`、现有窗口逻辑、Tauri bridge、本地 sidecar、桌面更新和视频桌面壳
- 保留旧音乐 API、旧 Rust 音乐命令和旧前端音乐源码作为暂存资产，先保证运行时不可达
- 为下一阶段新的 YesPlayMusic 模块预留稳定目录和边界契约

**不做**

- 不在本阶段直接接入新的 YesPlayMusic UI 或播放核心
- 不在本阶段全量删除 `src/features/music/**`
- 不在本阶段删除 `/api/music/*`
- 不在本阶段删除 Rust 音乐 IPC 命令
- 不在本阶段为旧音乐系统提供并行回退页
- 不在本阶段改变现有视频、直播、下载、更新、登录等主流程

**现状结论**

- 当前音乐功能不是单一路由页面，而是分散在根布局、导航、全局播放器根节点、桌面 tray、下载桥接和 `/api/music/*` 上
- 旧音乐播放器根节点目前以全局方式挂在应用布局中，因此只改 `/music` 页面无法真正停用旧音乐行为
- 现有桌面集成中，窗口配置、Tauri 命令、sidecar、本地配置和更新机制都已经稳定，不应为了重建音乐 UI 一并拆掉
- 旧音乐代码可以作为后续参考资产，但不应继续作为正式运行时的一部分

**核心方案**

1. 采用“软下线旧音乐、保留桌面基础设施”的方案，而不是立即做前后端全量删除
2. 先切断全局副作用，再切断用户入口，最后冻结旧模块
3. 让 `/music` 在过渡期成为稳定占位页，而不是 404、空白页或隐藏路由
4. 保留可复用的 Tauri/Rust/桌面壳能力，避免后续 YesPlayMusic 重建时重复造轮子
5. 新旧音乐系统必须通过清晰边界隔离，避免重建再次退化为在旧模块上缝补

**目标状态**

占位期完成后，系统应满足以下状态：

- 访问 `/music` 时只显示占位页
- 应用启动后不会自动恢复旧音乐播放现场
- 桌面 tray 中不再出现旧音乐播放控制
- 侧边栏和移动底部导航不再展示“音乐”入口
- 旧音乐下载、旧音乐设置、旧音乐快捷键和旧媒体会话联动不再被触发
- 视频、直播、下载、更新、登录、本地 sidecar 以及窗口逻辑保持可用
- 代码仓库中仍保留旧音乐相关基础设施，供后续重建复用或参考

**拆除边界**

保留的部分：

- `src-tauri/tauri.conf.json` 中的窗口配置、构建命令和 `externalBin`
- `src-tauri/src/main.rs` 与 `src-tauri/src/lib.rs` 中的桌面壳、sidecar、本地配置、更新器和主窗口生命周期
- `src/lib/desktop/tauri-client.ts` 中统一的 Tauri 前端桥接外观层
- 现有视频播放器、直播播放器、下载流程和公共桌面布局
- 旧 `/api/music/*` 与 Rust 音乐命令，前提是运行时不再被 UI 调用

临时下线的部分：

- `src/app/music/page.tsx` 对应的正式音乐页面内容
- 根布局中的旧 `MusicPlayerRoot` 全局挂载
- 侧边栏与移动底部导航中的“音乐”入口
- 旧音乐 tray 菜单与前端 tray 事件联动
- 旧音乐下载入口和旧音乐设置入口

**拆除顺序**

1. 先切断全局副作用
   - 根布局移除旧 `MusicPlayerRoot`
   - Tauri `setup` 阶段停用旧音乐 tray 安装
   - `/music` 路由替换为占位页
2. 再切断用户入口
   - 隐藏侧边栏“音乐”
   - 隐藏移动底部导航“音乐”
   - 隐藏旧音乐下载和旧音乐设置入口
3. 最后冻结旧实现
   - 旧 `src/features/music/**` 先保留但不允许运行时导入
   - 旧 `/api/music/*` 先保留但不作为活跃前端能力
   - 待占位版稳定后，再整体迁到 `src/features/music-legacy/`

**回滚点**

- 回滚点 A：全局副作用切断后，应用可启动，`/music` 为占位页，旧音乐不再自动播放
- 回滚点 B：入口切断后，用户无法从主导航进入旧音乐，但视频和桌面主流程不受影响
- 回滚点 C：旧模块冻结后，即使后续重建延期，也可只恢复入口与全局挂载做临时回滚，无需恢复底层桌面基础设施

**重建目录规划**

正式重建时采用以下目录结构：

```text
src/
  app/
    music/
      page.tsx
  features/
    music-legacy/
      ...旧音乐实现，仅供参考
    music/
      app/
      components/
      domain/
      services/
        providers/
          yesplaymusic/
        desktop/
        playback/
      state/
      tests/
  lib/
    playback/
      media-arbiter.ts
```

目录职责：

- `src/app/music/page.tsx`
  - 仅做路由入口装配
- `src/features/music/app/*`
  - 页面级容器与场景组装
- `src/features/music/components/*`
  - 新音乐 UI 组件
- `src/features/music/domain/*`
  - 统一实体、仓储接口、数据映射边界
- `src/features/music/services/providers/yesplaymusic/*`
  - YesPlayMusic 或上游音乐源适配层
- `src/features/music/services/desktop/*`
  - 桌面专属能力包装层
- `src/features/music/state/*`
  - 独立的音乐状态层
- `src/lib/playback/media-arbiter.ts`
  - 音视频互斥协调器

**边界契约**

1. UI 不直连 Tauri
   - React 组件不得直接导入 `@tauri-apps/api/*`
   - 桌面能力必须经过 `src/lib/desktop/tauri-client.ts` 或新的桌面服务层
2. UI 不直连第三方音乐源
   - 页面和 store 只消费统一领域实体
   - 上游接口差异只允许出现在 provider adapter 层
3. 音频互斥必须全局协调
   - 视频开始播放时，协调器暂停音乐
   - 音乐开始播放时，协调器暂停视频
   - 该逻辑不得散落在单个页面中
4. 路由层只做装配
   - `/music` 路由文件不承载播放器核心、网络请求或桌面 IPC 逻辑
5. 旧模块只读冻结
   - 迁入 `music-legacy` 后只允许参考，不允许新代码继续依赖

**验收标准**

占位期验收：

- `pnpm typecheck` 通过
- `pnpm desktop:check` 通过
- 桌面应用启动正常
- 访问 `/music` 显示占位页
- 侧边栏和移动底部导航不再展示“音乐”
- 旧音乐不会自动恢复播放，也不会继续占用音频输出
- tray 中不再出现旧音乐控制
- `/play`、`/live`、下载、更新、登录和 sidecar 功能无回归

重建准备阶段验收：

- 新 `music` 模块可以在不依赖旧运行时的前提下独立开发
- 新旧模块边界明确，后续可将旧实现整体迁移为 `music-legacy`
- 音视频互斥协调器拥有单独落点，不与任一页面耦合

**主要风险与缓解**

- 风险：只改 `/music` 页面，不移除根布局里的旧播放器挂载，旧音乐仍会后台运行
  - 缓解：先切断全局副作用，再处理路由和导航
- 风险：过早硬删除旧目录，导致布局、类型引用或桌面桥接编译失败
  - 缓解：先做不可达化软下线，再做冻结迁移
- 风险：后续重建时直接在旧模块上修补，重新引入边界耦合
  - 缓解：明确要求旧模块迁入 `music-legacy` 后只读参考

**下一步**

本设计批准后，下一阶段应先产出实现计划，再按“全局副作用切断 -> 入口切断 -> 占位页落地 -> 旧模块冻结”的顺序执行。
