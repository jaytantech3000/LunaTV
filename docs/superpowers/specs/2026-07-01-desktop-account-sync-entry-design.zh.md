# 桌面帐号同步入口开放设计

**目标**

让桌面端用户可以从现有用户菜单直接找到“帐号同步”入口，同时保留原有“管理面板”菜单及其 `/admin` 内容不变。

**范围**

- 仅调整桌面端用户菜单的可见入口。
- 新增独立“帐号同步”菜单项，跳转到 `/desktop-admin`。
- 保留现有“管理面板”菜单项，继续跳转到 `/admin`。
- 继续沿用现有权限判断：仅桌面端且当前账号为 `owner/admin` 时显示。

**非目标**

- 不修改 `/desktop-admin` 页面内容。
- 不修改 `/admin` 页面内容。
- 不新增新的权限模型或角色判断。
- 不把帐号同步入口开放给 Web 非桌面环境。

**现状问题**

- 帐号同步功能实际已经存在于 `/desktop-admin`。
- 用户菜单当前只有“管理面板”，跳转目标是 `/admin`。
- 这导致帐号同步入口在正常使用路径里不可发现。
- 如果直接把“管理面板”替换成 `/desktop-admin`，原先管理能力会被藏起来，信息架构会变差。

**方案对比**

1. 直接把“管理面板”改为 `/desktop-admin`
   - 优点：改动最小。
   - 缺点：原 `/admin` 被隐藏，语义错误。
2. 保留“管理面板”，新增“帐号同步”
   - 优点：语义清晰，原功能不丢，符合最小惊讶原则。
   - 缺点：菜单项增加一个。
3. 在 `/admin` 内增加跳转到 `/desktop-admin` 的二级入口
   - 优点：不增加用户菜单项。
   - 缺点：仍然多一步，不能解决“看不到入口”的核心问题。

**推荐方案**

采用方案 2：

- 桌面端 `owner/admin` 用户菜单继续保留“管理面板”。
- 在其旁边新增“帐号同步”菜单项。
- “帐号同步”直接跳转 `/desktop-admin`。

**交互设计**

- 桌面端用户菜单显示顺序保持稳定：
  - 设置
  - 管理面板
  - 帐号同步
  - 其他现有菜单项
- 新菜单项文案直接使用“帐号同步”，避免继续复用“管理面板”这种泛化名称。
- 新菜单项只在当前已有 `showAdminPanel` 条件成立时显示，避免引入第二套可见性分支。

**实现约束**

- 复用 `UserMenu` 现有导航反馈与 `prefetchRoute` 模式。
- 新增的菜单跳转目标为 `/desktop-admin`。
- `isOpeningAdmin` 一类的 pending 状态需要扩展为可区分 `/admin` 与 `/desktop-admin`，避免按钮 loading 状态串扰。
- 不改动现有 `showAdminPanel` 权限门禁。

**错误处理**

- 若重复点击当前正在跳转的目标，保持现有短路逻辑，直接关闭菜单或忽略重复导航。
- 若桌面环境判断失败，则不显示新入口，而不是展示不可用按钮。

**测试**

- `UserMenu` 桌面端 `owner/admin` 场景：
  - 同时显示“管理面板”和“帐号同步”
  - 点击“管理面板”仍跳 `/admin`
  - 点击“帐号同步”跳 `/desktop-admin`
- 非桌面或非 `owner/admin` 场景：
  - 不显示“帐号同步”
- pending navigation 场景：
  - `/admin` 与 `/desktop-admin` 的 loading 状态互不干扰

**风险与权衡**

- 风险很低，改动集中在菜单入口层。
- 主要风险是按钮状态复用导致两条导航的 pending UI 混淆。
- 通过把 pending 判断从单一路径扩展到目标路径级别即可收敛风险。
